# P7.4 rotation modes: design

Written by the `Plan` agent at P7.4 start (2026-10-07). Product rules are in `PLAN.md` → "Phase 7 rules". If this doc and `PLAN.md` disagree, `PLAN.md` wins. Balanced mode behaves exactly as before: every new column is nullable or defaults to balanced, and every new code path is behind a strategy.

## 1. Data model

| Change | Type / default | Backfill |
|---|---|---|
| `play_sessions.rotation_mode` | string(16), default `'balanced'`. Enum `App\Enums\RotationMode` (`balanced`, `mixed`, `skill_courts`, `winners_stay`, `king_of_court`). | Existing rows get the column default |
| `play_sessions.mode_settings` | json, nullable. Read through an accessor with a fixed key order, like `scoring` (MySQL reorders JSON keys). Shape: `{"winners_stay_max_wins":2,"skill_groups":[{"from_court":1,"to_court":2,"min_stars":4,"max_stars":6},…]}`. Null means defaults (max wins comes from `config('pickleq.rotation.winners_stay_max_wins')` = 2, no groups). | null |
| `players.gender` | string(8), nullable. Enum `App\Enums\Gender` (`man`, `woman`). | null |
| `matches.court_no` | Already exists. In winners stay and King of the Court (KotC) it is **also set on staged matches**, which binds them to a court. | – |
| `matches.court_group` | unsignedTinyInteger, nullable. The skill-group index of a staged match. | null |
| `session_players.pending_court`, `pending_from_match_id` | tinyint nullable, plus an FK to `matches` with `nullOnDelete`. Index on (`play_session_id`, `pending_court`). This is the per-court pool of incoming players. | null |

**Why the pool is stored, not derived.** Deriving it from match rows breaks in three cases:
- After a swap-out, the player's latest match falls back to the earlier done match, so they wrongly reappear in the pool.
- A return from break can only be detected by comparing `queued_at` and `finished_at` at second precision.
- Ordering "arrived" against "court staged" in the same transaction produces timestamp ties.

**When the pool columns change.** All writes happen inside the existing session lock:
- **Set** on finish, according to the routing rules.
- **Kept** while the player is in a staged match, so voiding that match returns them to the pool.
- **Cleared** on start, break, check-out, swap-out or remove, undo, void-done of the source match, mode switch, and court reduction.

`pending_from_match_id` records which pair a player arrived with. KotC needs this to split partners.

**What stays derived.** The winners-stay streak is computed by walking back through the done matches on court c while the same pair keeps winning.

## 2. Engine layer (pure PHP, `app/Domain/Rotation`)

**Refactor first, with no behaviour change.** Move cost and tie-breaking out of `BalancedRotationEngine` into `MatchCost` (`breakdown()`, `isBetter()`), and the priority sort into `Priority::sort()`. The existing unit tests guard the result.

**`Candidate`** gets a new field, `?Gender $gender = null`. Existing callers don't change.

**`MixedRotationEngine implements RotationEngine`**
- Takes the top `window` men and the top `window` women, then evaluates every pair of men × every pair of women in both 1M+1W splits (C(8,2)² × 2 = 1,568 evaluations).
- Skipped-priority is counted within each gender: `skipped = Σ(chosen men's ranks among men) − (0+1) + Σ(chosen women's ranks among women) − (0+1)`. Skipping one man or one woman costs exactly 1, the same as in balanced, and skipping someone because of their gender costs nothing. *(Changed in the P7.4b review. The first version summed overall ranks, so the cost of a skip depended on how many players of the other gender sat between.)*
- `pickReplacement` only picks a player of the opposite gender to the player left on the open team.

**`MatchCompleter::complete(fixed, rule, candidates, history)`** picks the 4 − |fixed| missing players from the window, using `MatchCost`. Rules:
- `SameTeam`: winners-stay holders stay partners.
- `SplitPairs`: players tagged with the same source pair are never partners.
- With 0 picks, it chooses the best split of the 4 given players (used for a full KotC pool).

**`WinnersStay::holders(courtResults, maxWins)`** works out the streak and decides whether the winners stay or the court resets.

**`LadderPlanner`**
- Inputs: the active ladder size B; for each court, whether it's busy and its pool (`PoolEntry{candidate, pairKey, arrivedAt}`); the queue; and the history.
- Output: a `CourtPlan{court, MatchResult, fromQueueIds, surplusIds}` for each free court that's ready.
- `route(court, B)` returns where the winners and losers go: a court number, or null for the queue.

**`SkillGroups`** is a value object. It parses and validates the groups, then answers `groupForStars()` and `courtRange()`. Valid groups:
- cover courts 1..courts exactly, in contiguous ranges
- cover stars 1–6 exactly
- number 2 or more

**`WaitEstimator`** gets `estimateFromMatchIndex()`. The existing `estimate()` wraps it.

## 3. Service layer

**Strategies.** `app/Services/Rotation/RotationStrategy` has 5 implementations, picked by `RotationStrategies::for($session)`:
- `Balanced` is today's code, moved.
- `Mixed` extends `Balanced`, uses the mixed engine and filters candidates by gender.

A `RotationQueries` helper holds `candidates`, `history`, `occupied`, `pending`, `busyCourts` and `createStaged(court_no, group)`.

**`MatchService`** keeps its public API, the transaction and lock shell, and the shared parts of finish, void and undo. It calls these strategy hooks:
- `refill`
- `allowedCourts(staged)`
- `afterFinish`
- `reroll`
- `replacementPool`
- `guardSwap`
- `reservedPlayerIds` (pending players count as occupied)
- `onUndo` / `onVoid`

| Action | Mixed | Skill courts | Winners stay (WS) | KotC |
|---|---|---|---|---|
| refill | The balanced loop with the mixed engine. A slot waits if there aren't 2 men and 2 women. | For each group: void surplus beyond `up_next_count`, then stage from that group's candidates. | For each free court with nothing staged, lowest court first:<br>• 2 holders → `complete(SameTeam)`<br>• 1 holder → clear it, then treat as 0<br>• 0 holders → a balanced match from the non-pending queue<br>Every match is staged bound to its court. | 1. Recompute B and clear pending above B.<br>2. Run the planner. A pool of 4 or more stages the 4 earliest arrivals and returns the rest to the queue.<br>3. Otherwise, if no busy feeder court will send players here, top up from the queue (`SplitPairs`). Otherwise, wait.<br>Free empty courts topped up in the same pass are filled by stars, highest on the lowest court. |
| start | unchanged | Lowest free court in the group. A manually chosen court must be in the group. | Must start on the bound court. Clears pending. | Same as WS |
| auto_fill | unchanged | Per group | Starts every bound staged match. Its court is always free. | Same as WS |
| finish | – | – | If the streak is below max wins, the winners get `pending_court = c`. | Winners → max(1, c−1). Losers → c+1, or the queue if c ≥ B. |
| re-roll | Leave-one-out with the mixed engine | Leave-one-out within the group | Holders are kept. Each challenger is left out in turn. | Only players who came from the queue can be re-picked. An all-pool match is refused with "use swap". |
| swap / remove | The incoming player must be the same gender. Remove picks the same gender. | Swap may cross groups. Remove picks from the group. | The incoming player can't be pending. The outgoing player's pending is cleared, and they join the plain queue. | Same as WS |
| void staged | Refill re-stages | same | Pending is kept, so the same holders are re-staged. | Same as WS |
| void playing | – | – | Players go to the plain queue (pending was cleared at start). The court is refilled normally. | Same as WS |
| void done | – | – | Clear pending for players whose `pending_from` is this match, void the staged matches that contain them, then refill. | Same as WS |
| undo | – | – | Clear pending for the 4 players, and **also void any staged match bound to that court**. Other players in the voided matches keep their pending. | Same as WS |

**Break or check-out while pending.** The existing `leaveQueue` voids the staged match, and now also clears pending. On return, the player joins the plain queue.

**Changing `courts` while live.**
- Skill courts: the form adjusts the last group's range. The change is rejected if a group would end up with no courts. Staged matches in the changed groups are voided.
- WS and KotC: staged matches bound to a removed court are voided, and players pending on those courts are cleared.

**Mode switch or group edit while live.** Void every staged match and clear all pending. Playing matches finish normally, and a finish is routed by whatever the session's mode is at that moment.

## 4. Rules settled during design

Rules 1–6 were flagged as product decisions. The outcome for each is recorded in `PLAN.md` → "Phase 7 rules".

1. In WS and KotC, `up_next_count` is ignored and hidden. Up Next is the per-court staged matches.
2. A WS holder pair broken by a break or check-out: see `PLAN.md`.
3. Whether skill courts are strict (no overflow to other groups): see `PLAN.md`.
4. A win cap on the KotC top court: see `PLAN.md`.
5. Voiding a playing match in WS or KotC means those players lose their holder or ladder spot.
6. With fewer than 4 × courts players, the KotC ladder shrinks to B = min(courts, ⌊(waiting + playing) / 4⌋). Without this, players pending on an unreachable court would starve.
7. A KotC pool bigger than 4 stages the 4 earliest arrivals. The rest go to the queue.
8. WS with max wins = 1 behaves like balanced. The form explains this.
9. With fewer than 2 challengers, WS holders stay pending and the court sits idle.
10. Gender changes go through a locked `CheckInService::setGender`, so refill runs straight away. The board has a quick M/W action.

## 5. UI impact

**Settings form**
- Mode select.
- Skill-group editor: court from–to and stars min–max.
- Max wins (1–5).
- `up_next_count` hidden for WS and KotC.
- Confirmation when switching mode while live.

**Board**
- Court cards show the next match bound to that court, a "waiting for players x/4" pool with where each player came from, a WS streak badge, and a crown on court 1 in KotC.
- The court picker is hidden for bound matches.
- Up Next and the waiting list are grouped by skill group.
- A "no gender, not placed" flag with a quick M/W action.
- Pending players are removed from the waiting list.

**TV and public page**
- A mode label.
- Each court shows its next match and its pool.
- Up Next is grouped by courts. Group labels look like "Courts 1–2" and never show stars.
- Pending players see "next on court N".
- The snapshot gains `mode`, `courts[].next`, `courts[].pending`, and `group` on Up Next and waiting rows.

**Wait estimates**

| Mode | Estimate |
|---|---|
| Balanced | Unchanged |
| Mixed | Match index = staged + ⌊rank within own gender / 2⌋ |
| Skill courts | Per group, using that group's courts, staged matches and queue |
| WS | staged + ⌊p / 2⌋, labelled as approximate |
| KotC | Remaining time on the bottom court + ⌊p / 2⌋ × the average match length |

Pending players get no minutes. They're shown as "next on court N".

**Player-facing forms**
- Self-register: an optional gender question.
- Self check-in: a player with no gender may set it but never overwrite it.
- Player form: a gender select. The player profile shows gender.
- Roster import: an optional `gender` column.
  - Accepted values, in any case: man, woman, m, w, male, female, f.
  - A blank cell never clears an existing value.
  - An invalid value makes the row an error.
